# Goal

기존 앱 구조와 디자인을 유지하면서 타입 안전한 화면과 네비게이션 흐름을 구현한다.

# When to use

화면, 탭, 스택, 모달, 공통 UI 컴포넌트를 새로 만들거나 기존 라우팅에 연결할 때 사용한다.

# Steps

1. 관련 `package.json`, 앱 진입점, 라우터, 네비게이터, 화면, 공통 컴포넌트, 스타일 파일을 읽는다.
2. 현재 라우팅 구조와 새 기능이 들어갈 위치를 판단한다.
3. 기존 디자인 톤과 재사용 가능한 컴포넌트를 확인한다.
4. 수정 또는 생성할 파일 목록과 짧은 구현 계획을 제안한다.
5. route params, props, API 응답, 로컬 상태의 TypeScript 타입을 확인한다.
6. UI, 상태관리, 네비게이션, 데이터 흐름 순서로 작게 구현한다.
7. 네비게이션 진입, 뒤로가기, 탭 전환, 재진입 연결을 확인한다.
8. 로딩, 빈 데이터, 오류 상태를 구현하거나 누락 위험을 보고한다.
9. typecheck, lint, 관련 테스트 또는 실행 검증을 수행한다.

# Rules

- 기존 라우팅 및 디자인 패턴을 우선한다.
- `any`를 피하고 route params와 컴포넌트 props를 명시한다.
- mock 데이터와 실제 API 코드를 구분한다.
- 새 패키지는 근거와 대안을 먼저 제시한 뒤 승인받는다.
- 요청과 무관한 화면이나 구조를 리팩터링하지 않는다.

# Output format

`구현 위치`, `변경 파일`, `구현 내용`, `검증 방법`, `남은 리스크` 순서로 요약한다.
