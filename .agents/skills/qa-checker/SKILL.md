# Goal

구현된 기능의 회귀 위험과 사용자 흐름 누락을 체계적으로 발견한다.

# When to use

기능 구현 또는 버그 수정이 끝난 뒤 QA 범위와 직접 확인 항목을 정리할 때 사용한다.

# Steps

1. 요구사항, 변경 파일, 관련 화면과 네비게이션 흐름을 읽는다.
2. 정상 케이스와 예상 결과를 정의한다.
3. 빈 데이터, 로딩, 오류 및 복구 동작을 확인한다.
4. 뒤로가기, 탭 이동, 재진입, 상태 유지 또는 초기화 동작을 점검한다.
5. 플랫폼별 차이와 주요 접근성 또는 터치 영역 위험을 확인한다.
6. 프로젝트의 typecheck, lint, test, build 관련 명령을 확인하고 가능한 검증을 실행한다.
7. 자동 확인 결과와 사용자가 기기 또는 시뮬레이터에서 직접 확인할 항목을 분리한다.

# Rules

- QA 요청에서는 앱 코드를 직접 수정하지 않는다.
- 실행하지 않은 검증은 통과로 표시하지 않는다.
- 재현 단계와 기대 결과를 구체적으로 작성한다.
- 빌드 성공을 정적 검사 성공과 동일하게 취급하지 않는다.

# Output format

`자동 검증 결과`, `시나리오 체크리스트`, `사용자 직접 확인`, `발견 문제`, `남은 리스크` 순서로 작성한다.
