# Goal

근거를 바탕으로 버그 원인을 좁히고 가장 작은 안전한 수정으로 해결한다.

# When to use

오류 메시지, 재현 경로 또는 예상과 다른 동작을 조사하고 수정할 때 사용한다.

# Steps

1. 실제 동작, 기대 동작, 환경, 재현 경로를 정리한다.
2. 오류 로그와 관련 화면, 컴포넌트, 훅, 네비게이션, 데이터 계층 파일을 확인한다.
3. 원인 후보를 근거와 함께 가능성 및 영향도 순으로 나열한다.
4. 가장 유력한 원인을 검증할 최소 진단을 수행한다.
5. 관련 없는 구조 변경 없이 가장 작은 수정으로 해결한다.
6. 원래 재현 경로와 인접 사용자 흐름으로 회귀 여부를 확인한다.
7. typecheck, lint, 관련 테스트와 수동 회귀 항목을 정리한다.

# Rules

- 원인을 확인하기 전에 추측만으로 광범위하게 수정하지 않는다.
- 증상 은폐보다 근본 원인 해결을 우선한다.
- 수정 범위를 최소화하고 기존 정상 동작을 보존한다.
- 재현하지 못한 경우 필요한 로그나 조건을 명확히 요청한다.

# Output format

`재현 경로`, `원인 후보`, `확인된 원인`, `수정 내용`, `회귀 테스트`, `남은 리스크` 순서로 작성한다.
