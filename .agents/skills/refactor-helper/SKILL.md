# Goal

외부 동작을 유지하면서 최소 범위로 코드 구조와 가독성을 개선한다.

# When to use

큰 파일, 반복 로직, 복잡한 함수 또는 재사용이 어려운 컴포넌트를 정리할 때 사용한다.

# Steps

1. 대상 파일과 호출부, props, 타입, 상태 및 부수효과를 읽는다.
2. 현재 구조와 보존해야 할 동작을 요약한다.
3. 가장 작은 리팩터링 단위와 영향 파일을 제안한다.
4. 동작 변경 없이 함수, 타입, 훅 또는 컴포넌트를 한 단계씩 분리한다.
5. 각 단계에서 import, 타입, 렌더링, 상태 수명주기와 네비게이션 영향을 확인한다.
6. typecheck, lint, 테스트 또는 수동 시나리오로 기존 동작을 검증한다.

# Rules

- 기능 추가와 리팩터링을 섞지 않는다.
- 공개 API와 사용자 동작을 유지한다.
- 변경 범위를 최소화하고 불필요한 파일 이동이나 이름 변경을 피한다.
- 새 추상화는 실제 중복 또는 책임 분리 근거가 있을 때만 만든다.

# Output format

`현재 구조`, `변경 범위`, `리팩터링 내용`, `검증 결과`, `위험도와 남은 리스크` 순서로 작성한다.
