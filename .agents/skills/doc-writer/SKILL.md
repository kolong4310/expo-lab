# Goal

현재 프로젝트 사실에 근거한 간결하고 실행 가능한 개발 문서를 작성한다.

# When to use

README, 온보딩 문서, 기능 설명, 운영 메모 또는 변경 기록을 만들거나 최신화할 때 사용한다.

# Steps

1. 문서 대상 독자와 목적을 확인한다.
2. `package.json`, 설정 파일, 실제 폴더와 관련 코드를 읽어 사실을 수집한다.
3. 설치 방법, 실행 방법, 폴더 구조, 주요 기능, 주의사항 중 필요한 항목을 구성한다.
4. 복사해 실행할 수 있는 명령과 필요한 사전 조건을 명확히 작성한다.
5. 추정 내용, 비밀값, 오래된 경로 또는 존재하지 않는 명령이 없는지 검토한다.
6. 변경된 구현과 문서가 일치하는지 최종 확인한다.

# Rules

- 개발자가 빠르게 훑을 수 있는 실무 문서 스타일을 사용한다.
- 설명을 반복하거나 불필요하게 장황하게 쓰지 않는다.
- 저장소에서 확인되지 않은 기능이나 명령을 사실처럼 쓰지 않는다.
- API 키와 실제 `.env` 값 대신 변수명과 안전한 자리표시자를 사용한다.

# Output format

문서 본문을 먼저 제공하고, 이어서 `근거로 확인한 파일`, `확인이 필요한 항목`, `변경 요약`을 짧게 정리한다.
