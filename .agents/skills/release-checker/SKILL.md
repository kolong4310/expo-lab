# Goal

릴리스 차단 요인과 수동 확인 항목을 빌드 또는 제출 전에 식별한다.

# When to use

EAS 빌드, 내부 배포, 프로덕션 빌드 또는 앱스토어 제출을 준비할 때 사용한다.

# Steps

1. `app.json`, `app.config.ts/js`, `eas.json` 등 실제 앱 설정 파일을 확인한다.
2. `package.json`의 scripts, Expo 및 React Native 버전, 빌드 도구 구성을 확인한다.
3. 앱 버전명과 Android versionCode, iOS buildNumber의 존재와 증가 여부를 점검한다.
4. 코드에 값을 노출하지 않고 필요한 환경변수 이름과 누락 가능성을 확인한다.
5. 권한, 아이콘, 스플래시, 번들 식별자, 패키지 이름, 서명 및 플랫폼 설정을 점검한다.
6. Android와 iOS 빌드 전 체크리스트를 각각 작성한다.
7. 스토어 문구, 스크린샷, 개인정보 처리방침, 권한 설명 등 제출 전 위험을 정리한다.

# Rules

- 비밀값과 인증서 내용을 출력하거나 변경하지 않는다.
- 버전 또는 빌드 번호를 요청 없이 변경하지 않는다.
- 확인된 사실, 추정 위험, 사용자 직접 확인 항목을 구분한다.
- 실제 빌드를 실행하지 않았다면 빌드 가능성을 확정하지 않는다.

# Output format

`설정 요약`, `Android 체크리스트`, `iOS 체크리스트`, `스토어 제출 위험`, `환경변수 점검`, `사용자 확인 항목` 순서로 작성한다.
