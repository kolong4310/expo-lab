# Goal

관련 변경만 포함하는 명확하고 검토 가능한 커밋을 준비한다.

# When to use

사용자가 커밋을 준비하거나 변경 파일 분류 및 커밋 메시지 제안을 요청할 때 사용한다.

# Steps

1. 저장소 루트에서 `git status --short`를 확인한다.
2. `git diff`와 필요하면 `git diff --staged`를 읽는다.
3. 변경을 기능, 버그 수정, 리팩터링, 문서, 설정 등 의도별로 분류한다.
4. 이번 커밋에 포함할 파일과 제외할 파일을 이유와 함께 제안한다.
5. 변경 내용에 맞는 간결한 한국어 커밋 메시지 3개를 제안한다.
6. 사용자의 명시적 승인을 기다린다.

# Rules

- 승인 전에는 stage 또는 commit하지 않는다.
- 사용자가 명시하기 전에는 push하지 않는다.
- 하나의 커밋에는 하나의 의도만 담는다.
- 비밀정보, 생성물, 관련 없는 사용자 변경을 커밋 대상으로 제안하지 않는다.
- diff 내용을 임의로 수정하지 않는다.

# Output format

`변경 요약`, `포함 제안`, `제외 제안`, `커밋 메시지 후보 3개`, `승인 필요 작업` 순서로 작성한다.
